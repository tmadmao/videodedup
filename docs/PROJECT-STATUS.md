## 一、停止开发的说明

本工具的功能已经完整，三个版本（v1.0 / v1.1 / v1.2）覆盖了最初设想的能力，
v1.2.1 又把项目审计发现的全部问题修复完毕。

**停止的原因是"没有新的具体需求"，而不是遇到了技术障碍或放弃维护。**
在没有明确需求的情况下继续改动，只会增加回归风险，因此在 v1.2.1 收尾。

这意味着：

- 不再有新功能、不再发布新版本、不再更新下载包；
- Issue / PR 不保证响应；
- **仓库保持公开可读，可自由 fork、修改、二次开发与再分发**（MIT 允许商用，
  只需保留版权声明）。

如果将来出现明确的新需求，可以基于 v1.2.1 的代码重新启动。

## 二、现有能力（v1.2.1 实测确认）

| 能力 | 状态 | 说明 |
|---|---|---|
| 递归扫描并完整列出视频 | 可用 | 无重复也完整显示；支持最小体积过滤、并发线程可调 |
| 元信息读取 | 可用 | `pymediainfo` 优先，`ffprobe` 兜底；**运行期不需要 ffmpeg** |
| 编解码覆盖 | 可用 | 实测 12 种：H.264 / H.265 8bit / **H.265 10bit** / VP9 / **AV1** / Xvid / MJPEG / WMV2 / MPEG-2(TS) / FLV / ProRes / MKV |
| 同源识别 | 可用 | 复制改名 / 二次转码 / 加水印 / 轻微裁切均可识别；**跨编码**（同一画面不同编码）也能判为一组 |
| 分组 | 可用 | 并查集 + 时长滑窗预筛 + **组代表互验**（防"连环并组"） |
| 「建议保留」 | 可用 | 逐级淘汰 + 近似平局容差 + 编码质量下限门，并显示判决理由；**结果可复现** |
| 缩略图比对 | 可用 | 封面（避开黑场）/ 内容帧 / 中间帧，三种一次生成、切换瞬时 |
| 列排序与平铺视图 | 可用 | 任意列点击排序，升降序切换 |
| 导出 | 可用 | CSV（UTF-8-BOM，Excel 直接打开不乱码）/ JSON（命令行） |
| 删除类操作 | 可用 | **只允许人工勾选 + 二次确认**；移入系统回收站，失败降级为移动到本地回收站文件夹，绝不做不可逆删除 |
| 命令行模式 | 可用 | `--scan` 批量扫描 + 报告输出，适合无人值守 |
| 免安装 exe | 可用 | PyInstaller 单文件约 100 MB，内置全部依赖 |
| 隐私 | 可核验 | 主程序**零网络请求**（无 `requests` / `urllib` / `socket` / `http` 导入），不上传视频或图片 |

界面回归脚本 `tools/gui_smoketest.py`（26 项检查）**会打开窗口**，
请务必在**桌面会话**下运行 —— 在无交互桌面的环境里运行可能挂起。

## 三、已知取舍与限制（如实记录，不再修复）

这些不是"未完成的 Bug"，而是已明确接受的设计取舍，写在这里是为了避免后来者误判。

1. **抗水印的主力是灰度通道，不是掩码。**
   掩码（忽略近黑 ≤32 / 近白 ≥240 像素）对**半透明水印基本无效** ——
   半透明水印合成后既不到 240 也不低于 32，掩码排除不到它。
   实测：不透明纯白块水印掩码增益 +4.8pp，半透明台标仅 +0.5pp。
   真正把水印副本认出来的是 32×32 灰度通道的逐像素差（SAD）。
   另外掩码会**抬高异源相似度**（实测 66.1% → 74.9%），略微压缩安全区。
   详见 README §3。

2. **pHash 只能判断"画面高度相似"，不判断"内容语义"。**
   以下情况容易产生误判，必须人工复核：同一系列 / 同一场景的不同视频、
   片头片尾很长且相同的不同视频、纯色或静态画面为主的视频。
   工具只给**分组建议**，删/移都必须人工勾选 + 二次确认。

3. **音频不参与比对。** 只有画面。做音频比对需要引入能解音频的依赖
   （如 PyAV，但其 wheel 内含 GPL 组件，会带来许可证问题），已评估并放弃。

4. **存在一个"既非黑也非白"的干扰盲区。** 中灰、半透明、彩色水印不在掩码的
   排除范围内；这类干扰依赖灰度通道的容忍度（默认 0.92，允许平均逐像素差 ≤ 20/255）。

5. **对时长差异敏感。** 时长容差默认 `10%` 或 `5 秒`（取较宽者），
   差异超过它的两个文件**不做比对**——这是防误判的取舍，代价是
   "同一内容被重新剪辑加长"这类副本可能不入组，需要调大容差后"重新分组"。

6. **`--no-mask` 在部分数据集上不改变结论。** 因为两条通道的 OR 门在阈值附近
   余量通常很宽，开关掩码可能不改变任何一对的判定（本项目的测试样本就是如此）。

7. **未做基准验证的场景**：超大规模目录（>1 万文件）的耗时与内存、
   缓存文件长期增长后的表现。缓存条目上限为 20000 条，缩略图缓存在系统临时目录，
   界面提供"清理缩略图缓存"按钮。

## 四、如何继续使用

- **普通用户**：从 [Releases](https://github.com/tmadmao/videodedup/releases/latest)
  下载 `VideoDedupTool.exe` 双击即可（不需要 Python、不需要 ffmpeg）。
- **想用源码**：解压 `videodedup-v1.2.1.zip`，双击 `安装依赖.bat`，再双击 `运行工具.bat`。
- **先自检**：`python video_dedup.py --selftest`。
- **批量模式**：`python video_dedup.py --scan "D:\视频库" --csv 报告.csv`。
